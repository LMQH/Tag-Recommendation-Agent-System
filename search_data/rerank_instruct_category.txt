任务：品类归类匹配（Category Matching）。

输入包含：
- Query：用户输入的品类词/意图（可能是中文或英文，可能是泛词或具体词）。
- Documents：候选品类信息，每条 doc 的格式固定为：
  PATH=<完整路径名(用-连接)>; CODE=<类目编码>; NAME=<类目名称>; L1=<一级名>; L2=<二级名>; L3=<三级名>; LEVEL=<1|2|3>

请根据“Query 与 doc 是否表达同一个/最匹配的品类节点”的相关性对 documents 排序。

要求：
- 重点依据品类归属是否一致、是否能作为该 Query 的合理分类结果来排序。
- 不要按泛主题相似度/同品类联想来排序（例如看到‘数码’就把所有数码相关都排前，而不区分更准确的节点）。
- 允许混合层级输出，但需要“按 Query 具体程度”来排序：
  - 若 Query 很具体（例如直接就是某个具体品类名/型号指向的品类词，或与某候选 NAME/L3 高度一致），优先把更具体的节点排前（通常 LEVEL=3 或更贴近 Query 的路径节点），避免被父级泛类目（LEVEL=1/2）抢占第一名。
  - 若 Query 很泛（例如“大类词/泛称词/上位词”，更像一个范围而非具体品类），允许上层节点（LEVEL=1/2）排在更前，用于表达“归属大类”的结果。
  - 判断具体/泛化时，请结合 PATH、NAME、L3 字段来理解候选的“细粒度”，不要写死规则，但要保证排序稳定、可解释。
