## 概述

项目的日志系统采用分层设计，主要由三个部分组成：

1. **Agno 日志器**：基于 Agno 框架的日志系统，负责记录 Agent 运行过程中的所有日志
2. **Web 中间件**：FastAPI 请求日志中间件，记录所有 HTTP 请求和响应信息
3. **Tool Hook**：工具调用钩子，统一捕获并记录所有工具调用信息

所有日志统一写入到同一个日志文件中（默认：`log/app.log`），支持日志轮转和级别控制。

## Agno 日志器

### 实现位置

`ecom_reco_agent/utils/agno_logger.py`

### 核心功能

Agno 日志器是项目的核心日志系统，基于 Agno 框架的自动识别机制实现。

#### 1. 自动识别机制

Agno 框架会自动识别名为 `"agno"` 的日志器。通过设置 `logger.propagate = False`，确保日志不会传播到根日志器，Agno 会自动使用该日志器。

```python
logger = logging.getLogger("agno")
logger.propagate = False  # 关键：Agno 会自动识别并使用这个日志器
```

#### 2. 双处理器设计

日志系统采用双处理器设计，分别处理文件输出和控制台输出：

- **文件处理器（RotatingFileHandler）**：
  - 记录所有级别（DEBUG 及以上）
  - 支持日志轮转（按大小）
  - 默认最大文件大小：10MB
  - 默认保留备份文件数：5 个

- **控制台处理器（StreamHandler）**：
  - 只输出 INFO 级别及以上（INFO/WARNING/ERROR）
  - 不输出 DEBUG 级别日志，避免控制台输出过多信息

#### 3. 日志格式

日志格式统一为：

```
%(asctime)s | %(levelname)-8s | %(name)s | %(message)s
```

示例：
```
2024-01-15 10:30:45 | INFO     | agno | 服务启动成功
```

#### 4. 提示词内容截断

文件日志处理器包含自定义过滤器 `FileDebugFilter`，用于：

- 识别提示词相关的日志（通过关键词匹配）
- 自动截断过长的提示词内容（超过 500 字符）
- 在截断位置添加提示信息，避免日志文件过大

识别关键词包括：
- `<your_role>`
- `your_role`
- `instructions`
- `系统提示`
- `工作流程`
- `可用工具`
- 等...

#### 5. 第三方库日志控制

为避免第三方库（如 httpx、httpcore、openai 等）产生过多日志，系统会：

- 将这些库的日志级别设置为 ERROR
- 禁用日志传播，避免干扰主日志系统

### 初始化函数

#### `setup_agno_logging()`

直接设置日志系统，接受参数：

- `log_level` (int): 调试级别（1 或 2）
  - 1: 只显示普通调试日志
  - 2: 显示所有调试日志
- `debug_level` (str): 日志级别（DEBUG/INFO/WARNING/ERROR）
  - DEBUG: Agent `debug_mode=True`
  - 其他: Agent `debug_mode=False`
- `log_dir` (str): 日志目录（相对于项目根目录）
- `log_file` (str): 日志文件名
- `max_bytes` (int): 单个日志文件最大字节数（默认 10MB）
- `backup_count` (int): 保留的备份文件数量（默认 5 个）

#### `setup_agno_logging_from_config()`

从配置字典设置日志系统，从配置文件中读取参数。

### 使用方式

在 Agent 初始化前调用：

```python
from utils.agno_logger import setup_agno_logging_from_config
from config.config_loader import get_logging_config

logging_config = get_logging_config()
setup_agno_logging_from_config(logging_config)
```

## Web 中间件

### 实现位置

`ecom_reco_agent/middleware/request_logging.py`

### 核心功能

`RequestLoggingMiddleware` 是一个 FastAPI 中间件，用于记录所有 HTTP 请求和响应的详细信息。

#### 1. 中间件设计

继承自 `starlette.middleware.base.BaseHTTPMiddleware`，在请求处理前后记录日志。

#### 2. 日志器与 Handler（独立实例、同文件）

中间件使用独立日志器（`agentos.request`），写入与 Agno **同一日志文件**，但**不共享 Handler 对象**：根据 Agno 现有 `RotatingFileHandler` 的 `baseFilename` / `maxBytes` / `backupCount` **新建**一份 Handler，避免多 Logger 并发 `emit` 时争用同一把锁及与 Agno 文件 Filter 耦合导致错乱。

#### 3. 记录内容

中间件记录以下信息：

**请求信息**：
- 请求方法（GET/POST 等）
- 请求路径
- 客户端 IP 地址

**响应信息**：
- **非流式**：响应状态码 + 完整耗时（毫秒）+ `request_id`
- **流式（SSE 等）**：`call_next` 返回后只记 **Stream started**（`header_ready_ms`），传输结束在 **`stream_complete`** 单行（`total_ms` / `ttfb_ms`，同一 `request_id`）
- 流内异常：`Stream error request_id=...`
- 路径级 INFO/DEBUG 由配置 `agentos.request_logging` 或环境变量控制（见配置 README）

#### 4. 日志格式示例

```
# 非流式
2024-01-15 10:30:45 | INFO     | agentos.request | Request: POST /api/chat from 127.0.0.1 request_id=abc123def456
2024-01-15 10:30:46 | INFO     | agentos.request | Response: 200 for POST /api/chat in 1234.5ms request_id=abc123def456

# 流式
... | INFO | agentos.request | Stream started: POST /runs ... status=200 header_ready_ms=50.0 request_id=...
... | INFO | agno | stream_complete request_id=... | POST /runs ... | status=200 | header_ready_ms=50.0 | total_ms=65000.0 | ttfb_ms=12000.0
```

### 注册方式

在 `agent/agent_os.py` 中，AgentOS 初始化时自动注册：

```python
from middleware.request_logging import RequestLoggingMiddleware
app.add_middleware(RequestLoggingMiddleware)
```

## Tool Hook 日志记录

### 实现位置

`ecom_reco_agent/utils/tool_hooks.py`

### 核心功能

Tool Hook 通过 Agno 框架的 `tool_hooks` 机制，统一捕获所有工具调用（包括自定义工具和内置工具包），在工具调用完成后记录日志。

#### 1. 钩子函数设计

`create_tool_hook()` 返回一个符合 Agno 框架要求的钩子函数，签名如下：

```python
def tool_hook(function_name: str, function_call: Callable, arguments: Dict[str, Any]) -> Any:
    # 执行工具调用并记录日志
    pass
```

#### 2. 日志记录时机

钩子函数在工具调用**完成后**记录日志（Post-hook），包含：

- 工具名称
- 调用参数（格式化后，避免过长）
- 执行结果（格式化后，避免过长）
- 执行状态（成功/失败）
- 执行时间（秒）
- 错误信息（如果有）

#### 3. 参数和结果格式化

为避免日志过长，系统会对参数和结果进行格式化：

- **参数格式化**（`_format_arguments`）：
  - 尝试转换为 JSON 字符串
  - 最大长度：200 字符
  - 超过长度自动截断并添加省略号

- **结果格式化**（`_format_result`）：
  - 字符串：直接使用，超过长度截断
  - 字典/列表：转换为 JSON，超过长度截断
  - 其他类型：使用 `repr()`，超过长度截断
  - 最大长度：300 字符

#### 4. 日志级别

工具调用日志使用 `DEBUG` 级别，`log_level=2`，这意味着：

- 只有在 `log_level=2` 时才会显示
- 文件日志始终记录（文件记录所有级别）
- 控制台不输出（控制台只输出 INFO 及以上）

#### 5. 日志格式示例

```
2024-01-15 10:30:45 | DEBUG    | agno | [TOOL_CALL] 工具: get_festivals_nearby | 状态: 成功 | 耗时: 0.123s | 参数: {"days_ahead": 30} | 结果: [{"name": "春节", "date": "2024-02-10"}]...
```

#### 6. 特殊处理：get_user_input 追踪

钩子函数对 `get_user_input` 工具进行特殊处理：

- 从 `fields` 参数中提取 `tracker_id`
- 记录已调用的 `tracker_id`，用于状态追踪
- 支持两种 `fields` 格式：
  - 字典格式：`{"fields": [...], "tracker_id": "xxx"}`
  - 列表格式：字段中包含 `tracker_id`

### 注册方式

在 `agent/agent_os.py` 中，创建 Agent 时传入钩子函数：

```python
from utils.tool_hooks import create_tool_hook

tool_hook = create_tool_hook()

agent = Agent(
    # ... 其他参数
    tool_hooks=[tool_hook],
)
```

## 配置说明

### 配置文件位置

日志配置在 `ecom_reco_agent/config/dev.json`（或其他环境配置文件）的 `logging` 部分：

```json
{
  "logging": {
    "log_level": 2,
    "debug_level": "DEBUG",
    "log_dir": "log",
    "log_file": "app.log",
    "max_bytes": 10485760,
    "backup_count": 5
  }
}
```

### 配置项说明

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `log_level` | int | 1 | 调试级别：1（普通调试）或 2（详细调试） |
| `debug_level` | str | "INFO" | 日志级别：DEBUG/INFO/WARNING/ERROR |
| `log_dir` | str | "log" | 日志目录（相对于项目根目录） |
| `log_file` | str | "app.log" | 日志文件名 |
| `max_bytes` | int | 10485760 | 单个日志文件最大字节数（10MB） |
| `backup_count` | int | 5 | 保留的备份文件数量 |

### 日志级别说明

- **DEBUG**：详细调试信息，包括工具调用详情
- **INFO**：一般信息，包括请求/响应、服务启动等
- **WARNING**：警告信息
- **ERROR**：错误信息
- **CRITICAL**：严重错误

### 日志轮转

日志文件按大小自动轮转：

- 当文件大小超过 `max_bytes` 时，自动创建新文件
- 旧文件重命名为：`app.log.1`, `app.log.2`, ...
- 最多保留 `backup_count` 个备份文件
- 超过数量的旧文件会被自动删除

## 使用示例

### 1. 在代码中使用日志

```python
from agno.utils.log import log_info, log_warning, log_error, log_debug, log_exception

# 记录信息
log_info("服务启动成功")

# 记录警告
log_warning("配置项缺失，使用默认值")

# 记录错误
log_error("API 调用失败")

# 记录调试信息（log_level=1）
log_debug("调试信息", log_level=1)

# 记录详细调试信息（log_level=2）
log_debug("详细调试信息", log_level=2)

# 记录异常
try:
    # 可能出错的代码
    pass
except Exception:
    log_exception("API 调用失败")
```

### 2. 查看日志文件

日志文件位于：`ecom_reco_agent/log/app.log`

可以使用以下命令查看：

```bash
# 查看最新日志
tail -f ecom_reco_agent/log/app.log

# 查看最近的 100 行
tail -n 100 ecom_reco_agent/log/app.log

# 搜索特定内容
grep "TOOL_CALL" ecom_reco_agent/log/app.log
```

## 总结

项目的日志系统采用统一设计，所有日志都写入同一个文件，便于查看和分析。主要特点：

1. **统一日志文件**：Agno 日志、Web 请求日志、工具调用日志都写入 `log/app.log`
2. **级别控制**：文件记录所有级别，控制台只输出 INFO 及以上
3. **自动轮转**：日志文件按大小自动轮转，避免文件过大
4. **内容截断**：自动截断过长的提示词和工具参数/结果，保持日志可读性
5. **统一格式**：所有日志使用统一的格式，便于解析和分析

通过这套日志系统，可以全面追踪 Agent 的运行状态、HTTP 请求处理情况以及工具调用详情，为调试和监控提供有力支持。
